# Reflection: upstreams-coordinator (series from lanes to upstream/ and the kernel branches)

Written 2026-11-23 for the steward's structure review. The lane is at rest; nothing changed while writing this.

## 1. What the role does

It keeps the queue of work headed upstream: patches, questions and corrections. It reads what the lanes built, checks the readiness class and the evidence, and prepares each series up to the author's sign-off.
It never sends, posts or mails anything. Kernel series leave only from the author's clone, with his Signed-off-by.

## 2. How a series travels today

**Where it is cut from.** There is no single place.
- The kernel clone is `~/Projects/surya-audio/linux`, with remotes origin (linux-phone-oco/linux) and pulpoff (linux-surya). It has about 16 local branches, e.g. `fix/tas2562-volume` and `dt/surya-wcd-rx-channel-map`.
- `~/Projects/walleye-build/linux-v7.3` uses the same object store. Its worktrees (`wt-k-*`) are mostly detached. Two are on branches, `topic/ufs-match-android` and `topic/ufs-hynix-quirks`.
- I cut PMIC v1 in a third place: a shallow clone of next-20261119, made in my scratchpad (`git am` the saved patches, then rebuild). It is gone when the scratchpad is cleaned, and it was gone once already.

**The tools.** Plain `git format-patch --cover-letter --base=<sha> -vN`, and `scripts/get_maintainer.pl` for the recipients.
- Checks: `checkpatch`, a W=1 build, and `lpoco-bringup dt-check binding|dtbs`.
- No b4. Nobody uses `b4 prep`/`b4 send`, so there is no b4 cover-letter branch and no change-id.

**Where it lands.** Since decision 2026-11-20-outgoing-items-live-in-upstream, the home is `docs/upstream/<list>/<item>/`: the .patch files, SEND-NOTES.md (base, evidence, open items, recipients, send command) and a README.
- The row is `ikb upstream-item --file auto`, and its state moves with `ikb upstream-state`.
- Versions: one folder per version (`pmic-wdt-gen2-v1/`), or one folder per item with v0/v1 inside (walleye-board-dts, panel s6e3fa5, from walleye PR 637). There is no single convention yet.
- Replies: none received so far, because nothing has been sent. Their planned home is the item row (`--reviewed-by`, state). No folder exists for lore threads.

**How it leaves.** The author re-authors in his clone:
- `git rebase --exec 'git commit --amend --no-edit --reset-author -s' <base>`
- then format-patch again and `git send-email`, as SEND-NOTES says.

**Older homes still on disk.**

  It is the queue from before docs existed, and its README was the first "patches ready to send". Its items should be checked against docs upstream/ rows (linux-sound, sm7150-mainline) and the folder retired. I have not done that check.

## 3. Topic branch per series on a mainline tag, and test kernels from a list

**What helps:**
- Every upstream item already has a row with its base sha (`--base=` in the patches), its destination list, its state and its readiness class. That is most of a manifest entry.
- `tad q carried` and the `--carried-in FORK/BRANCH` field already model "this patch lives on that fork branch until upstream takes it". That is the hook for one topic branch per series.
- The fork-tag convention (`FROMLIST(item-id): subject`, `bin/check-fork-tags.sh`) gives a way to check that a topic branch matches its item.
- Walleye already names some branches `topic/…`.
- dt-check and the W=1 build are scripted. They could run per topic branch.

**What blocks:**
- No canonical kernel repo or branch namespace. Series are cut from surya-audio/linux, from walleye-build worktrees (mostly detached heads) or from my scratchpad clone. "linux-topics" was a worktree of surya's clone, and I was told not to touch its remotes. A topic branch must live in one named place, pushed, not in a scratchpad.
- Bases differ: next-20261118/19 for upstream, v7.1 sm7150-mainline backports on surya, v7.2/v7.3 on walleye. One topic on a mainline tag means a rebase per base, or a stated rule (e.g. the topic on the latest -rc and the test kernel merges onto the lab's tag).
- The patches in docs are copies. Nothing ties `docs/upstream/<item>/*.patch` to a branch tip, so they drift. Better: the branch is the source, and docs holds the format-patch output plus SEND-NOTES, regenerated by a tool. Or docs keeps only SEND-NOTES and names the branch and tag.
- There is no tool that merges a written list of topics into a test kernel. The closest is the builders' kernel-build steps per lab. The list would have to say topic, its tag, and known-good evidence (which item rows and tests). The rows exist; the tool does not.
- Evidence crosses lanes by hand. The surya "PMIC bite" claim was copied from a PR title and was really an APSS bite. A topic marked known-good must point at a test record, not a title.

## 4. Hard to find, and the folders

**Hard to find:**
- Which tree and branch a series was cut from.
- Where a series lives: three homes at once until #726.
- Walleye's patches, which the author could not find; that is how the one-home decision started.
- Which kernel worktree is current, among many detached `wt-k-*` and `wt-*` worktrees.
- Which claim behind a series was measured, and by whom.

**Why it got confused** (research how-outgoing-series-got-two-homes):
- #469 put the first series in research/ and others followed.
- Nothing read at start named `upstream/`; only `--file auto` encoded it.
- The record accepts any path.

The briefs README was fixed by orchestration. The record's refusal and the AGENTS.md line wait on ikb's owner.

**The folders:**
- **docs-upstreams**: my own worktree of docs, for landing this lane's rows and files. It is a working copy, not a home: detached at origin/main between lands. It has now been removed from disk. That is fine, since nothing was open, and `git worktree add` recreates it.
- **upstream-queue**: the pre-docs queue (2026-11-17), plain files and not a repo. Its reason has expired. It should be reconciled with docs upstream/ rows and retired. I know of no current writer.

**One suggestion for the layout:**
- One kernel repo, linux-phone-oco/linux.
- `topic/<item-id>` branches, each on a stated mainline tag; the item row names the branch.
- docs `upstream/<list>/<item>/` holds SEND-NOTES and a generated `vN/` patch set per version sent.
- A list file (topic, tag, evidence ids), read by one tool that assembles the test kernel. Lanes test that kernel; known-good is written back to the row.
